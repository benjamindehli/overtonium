# Overtonium 1.8.0

A 32-partial additive synthesiser laid out like a 32-channel mixer. Every channel is one sine oscillator locked to a harmonic of the played note, and every channel has its own tuning, envelope and modulation.

## What is new in 1.8.0

**Three more factory presets, thirty-one in all.** All three lean on STRIKE, which arrived in 1.7.0 and is what lets one patch play two ways depending on how it is struck.

_Glockenspiel_ is a struck bar. The attack is the fastest the row goes and nothing sustains, so every partial rings down from the moment it is hit, each for its own length, from a third of a second out to three. The tone is not in the fundamental at all: the fourth and eleventh partials carry it and everything below them sits under one percent, which is what a bar does and a string does not.

_Dream Phase_ is a strike that becomes a pad, without either half being a layer. The attacks run from the fastest the row goes to the slowest it does, so the short partials are the transient and the long ones arrive behind them as it opens. Two partials step rather than glide, on a square each, the echo is nearly all feedback at a quarter of a second, and the converter is six bits at 22 kHz.

_Sparkle Pad_ is two instruments split by where a partial sits in the series rather than by layering. The bottom three sustain and take up to three quarters of a second to arrive, and everything from the fourth up attacks at once, sustains at nothing and is gone inside half a second. The delay runs the other way to the attack, so the bright half is already ringing by the time the pad opens underneath it.

## Fixed

**A session could open with the wrong preset showing as selected.** Factory presets sort alphabetically, so adding one moves every preset after it, and a session saved last year carried an index that now named a different sound. The sound itself was never in doubt, since a session stores its parameter values and nothing reloads a preset over them, but a host's own program menu would highlight a patch the session was not playing.

The saved state has always carried the preset's name alongside its index, and now the name decides. A name that matches a factory preset gives its current position, and anything else, which means one of your own or a patch edited past recognising, falls back to the index as before. Reordering the presets can no longer move a session onto a different one.

## Under it

**JUCE 9.0.2**, up from 8.0.15. Nothing in Overtonium needed changing for it, and the plugin sounds identical: every one of the forty-one audio examples on the site renders to the same samples before and after, checked against the signature FLAC stores of its own unencoded audio.

Two things move for anyone building from source rather than installing a binary. Linux now needs `libxi-dev` and `libegl-dev`, which JUCE 9 requires for XInput2 and for creating its OpenGL context through EGL. And the site's audio files all changed without the audio changing, because JUCE 9.0.1 builds libflac as C rather than C++ and encodes differently for it. Anyone diffing the repository and wondering what happened to the sound: nothing did.

## Upgrading from 1.7.0

Patches, presets and sessions load and sound exactly as they did.

**The factory presets are renumbered**, since the three new ones sort into alphabetical place rather than onto the end. The sound is stored with the session either way, so nothing changes underneath you, and the fix above means the name you saved now decides what the menu shows. A session saved before this release still knows which preset it was on.

**Automation is unaffected.** No parameter was added or removed, and there are still 781 of them.

## Installing

The [install page](https://benjamindehli.github.io/overtonium/install/#downloads) has a row per file saying who each one is for. In short: take the installer for your platform, or the zip beside it if you have no administrator rights or keep plugins somewhere of your own.

| Platform | Installer              | Formats                      |
| -------- | ---------------------- | ---------------------------- |
| macOS    | `.pkg`, with a chooser | VST3, Audio Unit, Standalone |
| Windows  | `.exe`                 | VST3, Standalone             |
| Linux    | none, use the zip      | VST3, LV2, Standalone        |

The macOS build is a universal binary and runs on both Apple Silicon and Intel. Logic and GarageBand only look for new Audio Units when they start, so restart them after installing.

On Linux the zip's contents go in `~/.vst3` and `~/.lv2`.

If you installed an earlier version with the package, the installer replaces it. A plugin folder holding two copies of Overtonium is worth tidying: macOS registers one of them and the host uses whichever that is, which need not be the newer.

## What has actually been tried

All three platforms are built on every push, run through both test suites, and put through pluginval at strictness 8. The VST3 also goes through Steinberg's own conformance validator, and both suites run again under the address and undefined behaviour sanitizers. macOS is the only platform where the plugin has been loaded into a real host, where the Audio Unit and the VST3 also pass `auval`. Nobody has run the Windows or Linux builds in a DAW yet, so treat those as untried and please open an issue with whatever you find.

The slide fix above is the one thing here that no test could have found. It came back from playing the instrument on an Expressive E Osmose, was traced from a description of how the gesture felt rather than from a failing check, and was confirmed the same way. There is now a test for the shape of it, written after the fact, which is the honest order.

## Windows will warn you

The Windows installer is not signed, so SmartScreen says the publisher is unknown. Choose "More info" and then "Run anyway". If you would rather not, build from source: the readme says how, and it takes one CMake command.

## macOS

The installer is signed and notarised, so it opens without a warning. It asks which of the three formats you want and installs only those.
